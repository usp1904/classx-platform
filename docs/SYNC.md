# Sync Contract: local ↔ Git ↔ Docker

Three layers must describe the same build. The **Git commit SHA** is the join key.

| Layer | Artifact | Proof |
|-------|----------|-------|
| Local | working tree | `npm run verify:sync` |
| Git | `HEAD`, `origin/*` | `git rev-list --left-right --count @{upstream}...HEAD` |
| Docker | image `classx-platform:verify-<sha>` | `/api/health` returns `commit == SHA` |

## Commands

```powershell
npm run verify:sync          # fast: tree, remote, secrets, port/branch/version contracts
npm run verify:sync:docker   # adds build + run + health-commit match
npm run verify               # full product gate (typecheck, check, coverage, tests, e2e)
```

Reports are written to `artifacts/sync-status.json` (ignored by Git).

## How the SHA flows

1. `git rev-parse --short=12 HEAD` — local truth.
2. `docker build --build-arg GIT_SHA=<sha>` — baked into the image (`ENV GIT_SHA`).
3. `GET /api/health` → `{ commit: "<sha>" }`.
4. Render sets `RENDER_GIT_COMMIT` automatically; the server reports it when `GIT_SHA` is absent.

## Runtime contract (kept in sync on purpose)

- Sessions use an in-process store with a Redis backend available when `initRedis()` is enabled; Compose must not start Redis/Postgres until the code opts in.
- `COOKIE_SECURE` is explicit. Local Docker uses `false` (plain HTTP); Render/VPS uses `true` (HTTPS).
- Server default port `8787` == Compose host port == Dockerfile healthcheck expectation.
- `render.yaml` branch must equal the current Git branch.
- `.env` and `.env.production` are never tracked; `.env.production.example` is the template.
- Local keys live in `.secrets` (gitignored, excluded from the Docker build context); `.secrets.example` is the template.

- `server/public` is generated by `npm run build` inside the Docker builder stage; it is never committed.

## Recursive improvement loop

Each pass must leave the next pass cheaper:

1. **Verify** — run `npm run verify:sync:docker`; read `artifacts/sync-status.json`.
2. **Triage** — any `fail` becomes a fix; any `warn` becomes a new check or an accepted note.
3. **Fix** — change the narrowest layer (source first, generated files last).
4. **Codify** — add a check for every drift found, so it can't regress silently.
5. **Commit** — one commit per drift class, conventional message.
6. **Push** — only after `verify:sync` shows `ahead 0, behind 0` and Docker parity passes.
7. **Repeat** — the checklist grows; the manual review surface shrinks.

Rule: never edit `server/public/**`, `server/data/**`, or `artifacts/**` to make a check pass. Fix the source and regenerate.
